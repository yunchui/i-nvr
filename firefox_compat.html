黑屏根因（已修正早期结论）
火狐走 hls.js + MSE 拿到 fMP4 分片后，需调用 Windows Media Foundation 的 HEVC 解码器；两路在线摄像头均为 HEVC。RDP 重连后会话主显示为 Display-Only 间接显示设备，MF Media Engine 在该上下文无法初始化 HEVC 解码，canPlayType 返回空，于是分片无法解码、永久"正在连接"。
早期"旧标签 404、刷新即恢复"和"默认 profile 损坏"的判断已被对照实验推翻：当前刷新、换 profile、清缓存、切换解码 pref 都无法恢复。
注：Mozilla Bug 2080409 指出，控制台看到的 MFCDM 报错只是"最后兜底"，更早的真实解码错误被 PDMFactory 隐藏；该缺陷 P2/S3 尚未修复。
可恢复方向（待拍板，未改动）： ① 在物理显示器/本地 console 会话（非 RDP）打开火狐；② 调整 RDP GPU 重定向/默认 GPU 后重连；③ 服务端对火狐按能力降级 AVC 或前端加 codec 检测与明确提示；④ WASM 软解。
前提：系统 HEVC 扩展 Microsoft.HEVCVideoExtension 2.4.149.0 已装且 Status Ok；换到未装该扩展的机器，火狐与 Edge 都可能无法解码 HEVC。
另：S1（甲辰万里·门口）"正在连接"是该摄像头本身无流（P4 独立项），与浏览器无关。
