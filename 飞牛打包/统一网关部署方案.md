# iNVR 走 fnOS 统一网关（UDS）部署方案

> 目标：Web 服务不单独暴露 TCP 端口，复用 fnOS 主站域名（5666/5667），自动带 HTTPS 与登录态，
> 通过官方「统一网关」以 Unix Socket 接入。RTSP 9554 仍独立开放。

## 1. 最终形态与请求链路

```
浏览器 ──> https://NAS:5667/app/com.indsvr.invr/...
              │
              └─ fnOS 统一网关（先校验 NAS 登录态，转发 X-Trim-* 头）
                    │  Unix Domain Socket
                    ▼
              target/app.sock  ──> Tomcat（不监听 TCP）
                                    context-path = /app/com.indsvr.invr
                                    /api/**、/hls/**
```

- 浏览器看不到独立 Web 端口，HTTPS / FN Connect 远程直接可用。
- 应用监听的是 `target/app.sock`（Unix Socket 文件），不是 TCP。
- 官方依据：`https://developer.fnnas.com/docs/core-concepts/gateway-registration/`

## 2. 已查证的应用现状（来自 input/app.jar）

| 项 | 现状 | 对网关的影响 |
|---|---|---|
| 框架 | Spring Boot 3.3.5 + 内嵌 Tomcat 10.1.31 | Tomcat 10.1 NIO 原生支持 `unixDomainSocketPath`，可行 |
| WebSocket | 无（纯 REST + HLS） | 网关支持 WS，本应用用不到，无适配负担 |
| API | `@RequestMapping("/api")` | 需挂到网关前缀下 |
| HLS | `/hls/{did}/index.m3u8`，m3u8 内分片为相对名 `seg-N.m4s` | 分片相对，无需改；但返回给前端的 `hlsUrl` 写死绝对路径 `/hls/{did}/index.m3u8`，需改 |
| 前端静态 | `/app.js`、`/style.css`、`/vendor/hls.min.js` 绝对路径 | 子路径下会 404，需改相对 |
| 前端 API | `fetch('/api/...')`、下载 `/api/recordings/...` 绝对路径 | 需改相对 |
| RTSP | 内嵌 RTSP 下行 9554 | 网关只代理 HTTP/WS，代理不了 RTSP，保持独立 |
| 自带登录 | 应用内「访问密码/门禁」 | 一期可保留，不接 fnOS 单点免密 |

## 3. 改造总览（关键：有两处必须改 Java 源码，脚本替代不了）

| 编号 | 改动 | 谁来做 | 能否纯脚本 |
|---|---|---|---|
| A1 | Tomcat 监听 UDS 的配置类（开关式，本地仍走 9080） | **改源码，重新编译 jar** | 否 |
| A2 | 后端 hlsUrl 去掉写死的前导 `/hls`（改相对） | **改源码，重新编译 jar** | 否（在编译 class 里） |
| B1 | index.html 加 `<base>`，静态资源改相对 | 打包脚本静态改写 jar | 是 |
| B2 | app.js 的 `/api/` 绝对路径改相对 | 打包脚本静态改写 jar | 是 |
| C1 | ui/config 改 gatewayPrefix/gatewaySocket | 模板改 | 是 |
| C2 | 注入 context-path，不再写 server.port | install_callback 改 | 是 |
| C3 | manifest 去掉 service_port/checkport | 模板改 | 是 |
| C4 | main 启动前清理残留 socket，传 UDS 路径 | 模板改 | 是 |

> 说明：这突破了最初「只给 jar、脚本全包、零改动」的前提。A1/A2 需要源码配合；
> 如果你只能拿到成品 jar、不能改源码，统一网关走不通，应回到端口直连方案。

## 4. A. 必须改 Java 源码

### A1. UDS 监听配置类（新增一个文件）

`com/invr/config/UdsTomcatConfig.java`，用环境变量 `FNOS_GATEWAY_SOCK` 做开关：
未设置时保持原 TCP（本地开发不受影响），设置时改监听 Unix Socket。

```java
package com.invr.config;

import org.apache.catalina.connector.Connector;
import org.springframework.boot.web.embedded.tomcat.TomcatServletWebServerFactory;
import org.springframework.boot.web.server.WebServerFactoryCustomizer;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class UdsTomcatConfig {

    @Bean
    public WebServerFactoryCustomizer<TomcatServletWebServerFactory> udsCustomizer() {
        return factory -> factory.addConnectorCustomizers((Connector connector) -> {
            String sock = System.getenv("FNOS_GATEWAY_SOCK");
            if (sock == null || sock.isBlank()) {
                return; // 本地开发：仍走 application.yml 的 server.port=9080
            }
            // 指定 UDS 后，Tomcat 不再监听 TCP port
            connector.setProperty("unixDomainSocketPath", sock);
            connector.setProperty("unixDomainSocketPathPermissions", "rw-rw----");
        });
    }
}
```

### A2. hlsUrl 改相对（DeviceController）

现状（字节码常量）：`"/hls/" + did + "/index.m3u8"`。
改为去掉前导斜杠的相对路径：

```java
// 改前
map.put("hlsUrl", "/hls/" + did + "/index.m3u8");
// 改后（配合页面 <base> 解析到网关前缀下）
map.put("hlsUrl", "hls/" + did + "/index.m3u8");
```

> m3u8 内部分片已是相对名 `seg-N.m4s`，无需改动。

改完重新 `mvn package` 产出新 jar，放入 `input/app.jar`。

## 5. B. 打包脚本静态改写 jar（build.bat 增加一步）

打包时解包 jar，改写 `BOOT-INF/classes/static/` 下文本，再回封。

### B1. index.html
- `<head>` 内加：`<base href="/app/com.indsvr.invr/">`
- `/style.css` → `style.css`
- `/vendor/hls.min.js` → `vendor/hls.min.js`
- `/app.js` → `app.js`

### B2. app.js
- 所有 `'/api/` → `'api/`（fetch、captcha、下载 href、删除等）
- `<a href="/api/recordings/...">` → `href="api/recordings/..."`
- 注意保留字符串内其它路径；改完需在浏览器实测一遍接口。

> 原理：页面落在 `/app/com.indsvr.invr/`（带尾斜杠），`<base>` 与相对路径都会解析到前缀下，
> 不再请求主站根。

## 6. C. FPK 模板与启动脚本

### C1. `app/ui/config`（替换现有端口式配置）
```json
{
  ".url": {
    "com.indsvr.invr.main": {
      "title": "iNVR",
      "icon": "images/icon-{0}.png",
      "type": "iframe",
      "protocol": "",
      "gatewayPrefix": "/app/com.indsvr.invr",
      "gatewaySocket": "app.sock",
      "url": "/app/com.indsvr.invr/",
      "allUsers": true
    }
  }
}
```
- `protocol`、`port` 被网关忽略，可不写。
- `url` 必须带尾斜杠，否则相对路径解析会掉一级。

### C2. `cmd/install_callback` 生成 `application-fnos.yml`
不再写 `server.port`，改写 context-path：
```yaml
server:
  servlet:
    context-path: /app/com.indsvr.invr
```
（JVM 内存配置保持不变。）

### C3. `manifest`
- 删除或注释 `service_port`、`checkport`（Web 已不监听 TCP）。
- RTSP 9554 不属于 service_port 托管范围，单独说明即可。

### C4. `cmd/main`（start 分支）
- 启动前删除残留 socket：`rm -f "${TRIM_APPDEST}/app.sock"`（Tomcat 发现文件已存在会启动失败）。
- 启动命令注入环境变量：
  `FNOS_GATEWAY_SOCK=${TRIM_APPDEST}/app.sock`
- 工作目录仍 `cd ${TRIM_PKGVAR}`（保持 `.invr/` 落盘）。

## 7. RTSP 9554
- 统一网关不代理 RTSP，9554 保持应用自行监听、局域网直连。
- 前端「复制 RTSP 地址」仍展示 `rtsp://NAS_IP:9554/...`，无需改。

## 8. 鉴权（一期可跳过）
- 网关已校验 NAS 登录态并转发 `X-Trim-Userid/X-Trim-Isadmin/X-Trim-Username`。
- 应用现有访问密码门禁可继续用；将来要做到 fnOS 单点免密，再在拦截器里读这些头，本期不做。

## 9. 联调与风险清单
1. 先在 Linux 上用 `curl --unix-sock target/app.sock http://localhost/app/com.indsvr.invr/api/session` 验证 UDS 通。
2. 装包后从桌面图标进，依次测：登录、设备列表、实时预览（m3u8 + 分片）、录像列表、下载、回放。
3. 重点验证 B2 改写后所有 `/api` 相对路径不漏网；漏网的会在浏览器控制台显示 404。
4. 升级/重启时确保旧 `app.sock` 被清理（C4）。
5. 前端若以后新增写死绝对路径的资源/接口，需同步改写。
